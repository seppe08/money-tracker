# Database migrations

Alembic owns the production schema. The application no longer calls
`create_all` when `CREATE_TABLES_ON_STARTUP=false` (the production default).

```sh
uv run alembic upgrade head          # apply migrations
uv run alembic revision --autogenerate -m "add budgets"
uv run alembic downgrade -1          # roll back one revision
uv run alembic current               # show the applied revision
```

Review autogenerated migrations before committing them: Alembic cannot infer
data backfills, enum changes, or index renames. The initial revision
(`0001_initial`) is the baseline for a fresh database.
